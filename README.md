# VELUNORA — متجر عطور فاخر (Next.js + Firebase)

متجر إلكتروني كامل بالعربية (RTL) والإنجليزية، مبني كتطبيق حقيقي متصل بمصادقة وتخزين وقاعدة بيانات،
مع لوحة إدارة آمنة وإرسال الطلبات إلى رقم واتساب يحدّده المالك. **لا توجد أي بيانات وهمية تُعامل كطلبات حقيقية،
ولا أي رابط مكسور.**

---

## 1) الحالة والمكوّنات

| الطبقة | التقنية |
|---|---|
| الإطار | Next.js 15 (App Router، TypeScript) + React 19 + Tailwind v4 |
| التخزين (محلي للتطوير) | ملفات JSON في `var/db` + صور في `var/uploads` (فوري بلا مفاتيح) |
| التخزين (الإنتاج) | Firebase: Firestore + Cloud Storage + Firebase Authentication |
| الملفات/الصور | `sharp` لتحويل الصور إلى WebP، رفع من الخادم فقط |
| البريد | `nodemailer` عبر SMTP (اختياري) |
| المصادقة | كوكي جلسة HttpOnly موقّع (HMAC) من الخادم + Firebase Auth لإشارة Google |

يوجد **محرّكان** خلف واجهة واحدة (`StoreDriver`) يُختار بينهما بمتغير `STORAGE_DRIVER`:
- `local` — للتشغيل والاختبار الفوري بلا أي مفاتيح خارجية.
- `firebase` — للإنتاج.

الواجهة البرمجية والعقود موثّقة في `CONTRACTS.md`.

## 2) التشغيل السريع (المحرّك المحلي، بلا Firebase)

```bash
npm install
copy .env.example .env.local        # ويندوز   (على لينكس: cp .env.example .env.local)
npm run seed                        # إدخال 8 منتجات مع صور WebP مولّدة
npm run admin:create -- --email owner@example.com --password "كلمة مرور قوية" --role owner
npm run dev                         # http://localhost:3000
```

- واجهة المتجر: `http://localhost:3000`
- لوحة الإدارة: `http://localhost:3000/admin/login` ← سجّل بالبريد وكلمة المرور أعلاه.
- **لا يوجد** رابط تسجيل لإدارة المتجر في أي مكان عام.

> في المحرّك المحلي تُنشأ الملفات في `var/db` تلقائيًا عند أول تشغيل.
> أبقِ `STORAGE_DRIVER=local` في التطوير فقط.

## 3) متغيرات البيئة

انسخ `.env.example` إلى `.env.local` وعبّئ القيم. المهمة:

| المتغير | الشرح |
|---|---|
| `STORAGE_DRIVER` | `local` أو `firebase` |
| `SESSION_SECRET` | **إلزامي في الإنتاج** — مفتاح سري طويل (≥16 حرفًا) لتوقيع الجلسات. أنشئه بـ:<br>`node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` |
| `APP_URL` | **إلزامي في الإنتاج** — الرابط العام للمتجر (مثال `https://velunora.com`). تُبنى عليه روابط البريد (التأكيد/إعادة التعيين/الفاتورة)، وبدونه **يرفض الخادم بناء الروابط** ولا يعتمد على ترويسة `Host` إطلاقًا (حماية من تسميم الروابط / Host header injection). في التطوير فقط يمكن تركه فارغًا فيُستخدم مضيف الطلب الحالي. يقبل أيضًا `NEXT_PUBLIC_SITE_URL` أو `NEXT_PUBLIC_APP_URL` كبديل. |
| `SETTINGS_ENCRYPTION_KEY` | مفتاح تشفير إعدادات المتجر الحسّاسة (كلمة سر SMTP) بـ AES-256-GCM. أنشئه بـ:<br>`node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`. القيم القديمة غير المشفّرة تبقى مقروءة (توافق خلفي). |
| `TRUSTED_PROXY_HOPS` | عدد الوسطاء الموثوقين أمام الخادم لقراءة عنوان العميل من `x-forwarded-for`. `0` (الافتراضي) = لا تثق بالترويسة واستخدم `x-real-ip` أو `local`؛ `1` خلف وكيل/موازن واحد موثوق. |
| `NEXT_PUBLIC_FIREBASE_*` | إعدادات تطبيق الويب من Firebase Console (عامّة، تُرسل للمتصفح) |
| `FIREBASE_SERVICE_ACCOUNT_KEY_PATH` | مسار ملف حساب الخدمة (سرّي، لا يُرفع للمستودع) |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | بديل: محتوى حساب الخدمة كسلسلة JSON |
| `NEXT_PUBLIC_GOOGLE_AUTH_ENABLED` | `true` لتفعيل زر «الدخول بجوجل» (يتطلب Firebase + OAuth Client) |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | معرّف عميل OAuth |
| `NEXT_PUBLIC_ALLOW_DEV_RESET_LINKS` | في التطوير فقط: يُظهر روابط إعادة التعيين في الاستجابة عند تعطّل SMTP. **لا تفعّله في الإنتاج** |
| `NEXT_PUBLIC_SITE_URL` | رابط الموقع العام (تُبنى عليه روابط البريد: التأكيد/إعادة التعيين) |
| `VELUNORA_DATA_DIR` / `VELUNORA_UPLOAD_DIR` | (اختياري) تغيير مجلدات المحرّك المحلي |
| `SMTP_*` أو إعدادات SMTP من لوحة الإدارة | بيانات خادم البريد لإرسال رسائل التأكيد/إعادة التعيين |

> **مهم:** لا تُلتزم بـ `.env.local` أو ملف حساب الخدمة في git (مغطّاة في `.gitignore`).

## 4) إنشاء حساب مدير

لا يوجد تسجيل مدير من الموقع. طريقتان:

1. **سكربت الخادم** (موصى به):
   ```bash
   # مالك بكل الصلاحيات
   npm run admin:create -- --email owner@example.com --password "..." --name "مالك المتجر" --role owner
   # موظف بصلاحيات محددة
   npm run admin:create -- --email staff@example.com --password "..." --role staff --permissions products,orders
   ```
2. **لوحة «الموظفون»** (للمالك فقط): أضف حسابًا مسجَّلًا مسبقًا عبر إدخال `UID` وبريده.

الصلاحيات: `products | orders | customers | settings | home | pages | audit`. المالك (`owner`) يملك الكل.
للتفعيل السريع للطلبات يجب أولًا ضبط **رقم واتساب المدير** من: الإدارة ← الإعدادات ← (تاب المالك).

## 5) ربط Firebase (الإنتاج)

### أ) إنشاء المشروع
1. أنشئ مشروعًا في <https://console.firebase.google.com>.
2. **Build → Authentication → Sign-in method:** فعّل **Email/Password**. (وللـ Google: فعّل Google وأضف OAuth Client من Google Cloud، ثم ضع معرّفه في `NEXT_PUBLIC_GOOGLE_CLIENT_ID`.)
3. **Build → Firestore Database:** أنشئ قاعدة بيانات (وضع Production).
4. **Build → Storage:** أنشئ Bucket.

### ب) إعدادات تطبيق الويب (عامّة)
- **Project settings → Your apps → Web app** → انسخ القيم إلى `NEXT_PUBLIC_FIREBASE_API_KEY` … `NEXT_PUBLIC_FIREBASE_APP_ID`.

### ج) حساب الخدمة (سرّي)
- **Project settings → Service accounts → Generate new private key** → احفظ الملف **خارج المستودع**.
- ضع مساره في `FIREBASE_SERVICE_ACCOUNT_KEY_PATH` أو محتواه في `FIREBASE_SERVICE_ACCOUNT_JSON`.

### د) تشغيل المحرّك
```
STORAGE_DRIVER=firebase
```
### هـ) نشر القواعد والفهارس
الملفات جاهزة في المشروع (`firestore.rules`, `storage.rules`, `firestore.indexes.json`). انشرها بـ:
```bash
npm i -g firebase-tools
firebase login
firebase use <project-id>
firebase deploy --only firestore:rules,firestore:indexes,storage
```
القواعد **تغلق كل وصول مباشر من المتصفح** إلى Firestore/Storage؛ كل شيء يمر عبر الـ API على الخادم (Admin SDK)،
ما يمنع تغيير الأسعار أو الحالات أو صلاحيات المدير من المتصفح نهائيًا.

### و) تعبئة المنتجات في Firestore
```bash
npm run seed        # يرفع المنتجات إلى Firestore (الصور محليًا في public؛ استبدلها من لوحة الإدارة عند النشر)
```

## 6) إعداد واتساب (إرسال الطلبات)

1. الإدارة ← **الإعدادات** ← تاب المالك: أدخل **رقم واتساب المدير مع رمز الدولة بدون +** (مثال: `966555555555`) واحفظ.
2. عند إتمام أي طلب، يحسب الخادم رسالة الطلب ويُرجع رابط `wa.me` — **لا يُعرض الرقم في الواجهة إطلاقًا**.
3. بعد التأكيد، تُفتح محادثة واتساب برسالة جاهزة موجّهة **لرقم المالك فقط**. يجب على المستخدم **الضغط على «إرسال» داخل واتساب** —
   الموقع لا يرسل تلقائيًا (هذا غير ممكن تقنيًا من الويب دون API رسمي).

> **الإرسال الآلي الكامل** يتطلب **WhatsApp Business Platform** (Cloud API) مع رقم أعمال موثّق وموافقة Meta،
> وإرسال من الخادم. البنية الحالية جاهزة لإضافة ذلك لاحقًا (الرسالة تُبنى على الخادم في `src/lib/server/whatsapp.ts`)
> دون إعادة بناء المتجر.

## 7) إعداد البريد (اختياري)

- من لوحة الإدارة ← الإعدادات: فعّل SMTP وأدخل المضيف/المنفذ/المستخدم/كلمة المرور/المرسل.
- دونه، تُرسل رسائل التأكيد/إعادة التعيين عبر رابط يظهر في الاستجابة **في التطوير فقط**
  (`NEXT_PUBLIC_ALLOW_DEV_RESET_LINKS=true`). في الإنتاج يلزم SMTP مضبوط.

## 8) النسخ الاحتياطي والاستعادة

```bash
npm run db:backup
```
- المحرّك المحلي: يحفظ `backups/velunora-backup-<وقت>.json` (كل ملفات `var/db`) + نسخة من `var/uploads`.
- Firebase: يصدّر مجموعات Firestore إلى ملف JSON واحد.

```bash
npm run db:restore -- --file backups/velunora-backup-XXXX.json
npm run db:restore -- --file backups/velunora-backup-XXXX.json --uploads backups/uploads-XXXX   # المحرّك المحلي
```

**لنسخة كاملة على Firebase** (موصى به دوريًا):
```bash
gcloud firestore export gs://<bucket>/backups/$(date +%F)
gcloud storage cp -r gs://<bucket> ./backups/storage-$(date +%F)   # نسخ الصور
```
خطة مقترحة: نسخة يومية آلية + الاحتفاظ 30 يومًا + اختبار استعادة شهري.

## 9) الأمان (ملخّص)

- لوحة الإدارة محميّة على الخادم في **كل** مسار (`requireAdminApi`) وفي تخطيط الصفحة (`requireAdminPage`)، وليست مجرد أزرار مخفية.
- لا توجد كلمة مرور إدارية ثابتة في الواجهة، ولا صلاحيات تُمنح من قيمة يرسلها المتصفح.
- الأسعار والخصومات والشحن والضريبة والمخزون والأرقام تُحسب **على الخادم** داخل معاملة ذرّية؛ العميل يرسل المعرّفات والكميات فقط.
- منع الطلبات المكررة عبر `idempotencyKey` مخزّن داخل المعاملة.
- جلسة بكوكي HttpOnly + `SameSite=Lax` + `Secure` في الإنتاج، وتوقيع HMAC.
- تحديد معدّل المحاولات (دخول/تسجيل/إعادة تعيين) + رسائل خطأ لا تكشف وجود الحسابات.
- سجل تدقيق لكل إجراء إداري مهم (من/ماذا/متى).
- حساب العميل المعطّل لا يمكنه الدخول ولا الطلب (فحص على الخادم لا في الواجهة).
- لا حذف نهائي لحسابات العملاء من الواجهة (تعطيل فقط) حفاظًا على السياسات وسجلات الطلبات.
- **إبطال الجلسات فورًا**: لكل حساب `sessionVersion`؛ تغيير/إعادة تعيين كلمة المرور أو تعطيل الحساب يزيده فتصبح كل الجلسات القديمة (على كل الأجهزة) باطلة. الجهاز الذي غيّر كلمة المرور يحصل على جلسة جديدة تلقائيًا.
- **عنوان العميل الموثوق**: لا يُقرأ `x-forwarded-for` إلا عند ضبط `TRUSTED_PROXY_HOPS`؛ وإلا يُستخدم `x-real-ip`/`cf-connecting-ip`. تحديد معدّل إضافي لكل بريد في تسجيل الدخول (8 محاولات/15 دقيقة) لمنع التخمين من عناوين متعددة.
- **أرقام طلبات غير قابلة للتخمين**: صيغة `VN-<عدّاد>-<4 رموز عشوائية>` بدل تسلسل مكشوف.
- **تتبّع الطلبات والفاتورة**: تطابق رقم الجوال **كاملًا** بعد التطبيع (مع استثناء ضيّق لرمز الدولة/الصفر البادئ)؛ وغير صاحب الطلب لا يستطيع تحديد بريد حرّ لإرسال الفاتورة (يُقيَّد بالبريد المسجّل في الطلب) لمنع استخدام الموقع كرُخّاصة بريد.
- **كلمة سر SMTP مشفّرة** بـ AES-256-GCM (`SETTINGS_ENCRYPTION_KEY`) ولا تُعاد للواجهة أبدًا (يُعاد علم `hasPassword` فقط).
- **صلاحيات الرفع بحسب النوع**: رفع صور المنتجات يتطلب `products`، وصور الرئيسية/البانرات `home`، والشعار/الأيقونة `settings`.
- **حماية الحذف من الخروج عن المجلد** في المخزنين المحلي وFirebase، وعدم كشف أخطاء Firebase الخام (تُترجَم «بيانات الدخول غير صحيحة» موحّدة).
- كلمة المرور: **8 أحرف على الأقل** (سياسة موحّدة خادمًا وواجهة).

## 10) النشر (مثال: Vercel)

1. ارفع المشروع إلى مستودع git.
2. أضف متغيرات البيئة (بما فيها `SESSION_SECRET` وFirebase وحساب الخدمة) في منصة النشر.
3. `STORAGE_DRIVER=firebase` و`NEXT_PUBLIC_ALLOW_DEV_RESET_LINKS=false`.
4. اضبط `NEXT_PUBLIC_SITE_URL` على رابط موقعك، وأضف النطاق إلى **Authorized domains** في Firebase Auth.
5. انشر قواعد Firestore/Storage (القسم 5-هـ).

> المحرّك المحلي (`local`) مخصّص للتطوير/الاستضافة الذاتية أحادية الخادم فقط؛ على منصات serverless استخدم `firebase`.

## 10-ب) رابط للعملاء (شبكة محلية / رابط عام مؤقّت)

**على نفس الشبكة (واي فاي المتجر):**

- من أي جوال/تابلت على نفس الشبكة: `http://<IP-الجهاز>:3000` (مثال: `http://192.168.3.174:3000`).
- إن لم يُفتح: اسمح للـ Node بمنفذ 3000 في جدار الحماية (Windows Defender Firewall ← Allow an app ← Node.js).

**رابط عام مؤقّت (يُرسل للعملاء):**

```bash
npm run share
```

- يعطيك رابطًا مثل `https://xxxx-yyyy.trycloudflare.com` — افتحه من أي مكان في العالم.
- يعمل طالما: الجهاز **مفتوح ولا ينام** + `npm start` + أمر `npm run share` شغّالان.
- عند إيقاف الأمر/إعادة تشغيله يتغيّر الرابط، وخدمة «quick tunnel» بلا ضمان تشغيل (مناسبة للتجربة/العرض، لا للبيع الجاد).
- للإيقاف: `Ctrl + C` في نافذة الأمر، أو `Stop-Process -Name cloudflared -Force`.

> **للبيع الفعلي:** تحتاج نطاقًا ثابتًا + استضافة دائمة — إمّا VPS (يبقى المحرّك `local` مع نسخ احتياطي دوري) أو نشرًا سحابيًا مثل Vercel مع `STORAGE_DRIVER=firebase` (لأن serverless بلا قرص دائم). راجع القسم 10 والقسم 5.

## 10-ب-2) لماذا رابط GitHub يعرض «كلامًا فقط»؟

هذا **طبيعي وليس خطأً في المتجر**:

- **GitHub** يعرض محتوى المستودع (الملفات + الـ README) كصفحة نصية لتوثيق المشروع. هو مكان *الشيفرة*، وليس مكانًا لتشغيلها.
- **GitHub Pages** خدمة **ملفات ثابتة فقط** (HTML/CSS/JS جاهزة). متجر VELUNORA تطبيق **Next.js بخادم Node** (واجهات API + جلسات + قاعدة بيانات)، فلا يمكن تشغيله على GitHub Pages إطلاقًا.
- لذلك فتحُ رابط المستودع أو رابط Pages يُظهر الـ README/الملفات فقط — وهذا متوقّع. *(تم تحسين هذا: صفحة Pages الآن تعرض **صفحة هبوط تعريفية فخمة** بكرت توضيح + زر «افتح المتجر الشغّال» بدل الـ README الخام — راجع `index.html` في جذر المستودع.)*

**خيارات التشغيل الحقيقية:**

| الخيار | يصلح لـ | المحرّك | ملاحظات |
| --- | --- | --- | --- |
| رابط مؤقّت (cloudflared) | عرض سريع للعملاء الآن | `local` | الرابط يتغيّر عند إعادة التشغيل، ولا يبقى بعد إغلاق جهازك |
| VPS / Docker | تشغيل دائم | `local` | مع نسخ احتياطي دوري لمجلد `var/` |
| Vercel + Firebase | نشر سحابي | `firebase` | الأفضل للاستمرارية (serverless بلا قرص دائم) |

## 10-ج) الواجهة الليلية والصور الحقيقية

واجهة المتجر التسويقية (الرئيسية + قائمة المنتجات + صفحة المنتج) بمزاج **ليلي فخم** (بنفسجي ملكي داكن + ذهب) مع صور عطور حقيقية، بينما تبقى صفحات **السلة والدفع والحساب وتتبّع الطلب والسياسات فاتحة** للوضوح وسهولة القراءة.

### كيف يعمل؟

- في `src/app/(shop)/layout.tsx` سكربت صغير يضيف الصنف `night` إلى `<html>` حسب المسار:
  - **ليلية:** `/` و `/products` و `/product/<slug>`.
  - **فاتحة:** كل ما تبقّى (`/cart`، `/checkout`، `/account`، `/order/*`، `/auth/*`، `/p/*`).
- الثيم كله في `src/app/globals.css` تحت `html.night { … }` — يعيد تعريف رموز Tailwind (`--color-bg`، `--color-ink`، `--color-cream`، `--color-line`، `--color-muted`، `--color-gold`…)، لذلك ينقلب التصميم كاملًا تلقائيًا دون تعديل المكوّنات.
- لإلغاء الواجهة الليلية: احذف السكربت من `(shop)/layout.tsx` أو احذف كتلة `html.night` من `globals.css` — يعود المظهر الفاتح كما كان فورًا.

### الصور

- مكانها: `public/brand/photos/*.webp` (مُحسّنة بـ WebP، بخلفيات علمية/داكنة تناسب النص الأبيض فوقها).
- تُسند في `var/db/settings.json`:
  - `home.heroImage` → خلفية البطل (مثال: `/brand/photos/hero-night.webp`).
  - `home.banners[].image` و `home.sections[].image` → بانرات الصفحة الرئيسية.
- أدوات مساعدة جاهزة في `tools/`:
  - `tools/fetch-photos.mjs` + `tools/scan-photos.mjs`: جلب/فرز صور مجانية الترخيص (Pexels License) وبناء لوحات مقارنة.
  - `tools/patch-home.mjs`: إسناد الصور للبانرات/البطل في `settings.json`.
  - `tools/analyze-shots.mjs`: تحليل لقطات الشاشة (متوسط السطوع ونسبة الأبيض) للتأكد أن الواجهة داكنة فعلًا.
- **الترخيص:** صور Pexels مجانية للاستخدام التجاري بلا حقوق وبلا إلزام بالإسناد. **للبيع الجاد:** استبدلها بصور منتجاتك الحقيقية من **لوحة الإدارة ← الرئيسية وإعدادات الهوية** (رفع صورة للبطل/البانر) — نفس المسارات تُستخدم بلا تعديل كود.

## 10-د) الفاتورة (شكل واقعي فخم)

نظام الفاتورة يعرض **مستندًا حقيقيًا** لا صفحة بيضاء: إطار ذهبي مزدوج، علامة مائية، ترويسة بالشعار، شبكة بيانات، لوحة العميل/الشحن، جدول أصناف بصور مصغّرة، إجماليات بشريط ذهبي، وختم حالة دائري.

### الشاشة مقابل الورق

| | على الشاشة | عند الطباعة / حفظ PDF |
|---|---|---|
| الخلفية | عنّابي داكن متدرّج (`#17102c → #0d0720`) | كريمي `#fffdf9` |
| الحبر | `#f6f0ff` | بنفسجي غامق `#241238` |
| الذهب | `#d9b877` | `#a8843c` |
| العلامة المائية | ظاهرة | مخفية |

**لماذا نسخة الطباعة فاتحة؟** لأن المتصفحات لا تطبع الخلفيات الداكنة افتراضيًا (وحتى مع `print-color-adjust: exact` قد يتجاهلها الطابور/المتصفح)، فتخرج ورقة بحبر أبيض على أبيض = غير مقروءة. لذلك الشاشة داكنة فخمة، والورق كريمي بهوية ذهبية/بنفسجية واضحة — وليس صفحة بيضاء عادية.

- الألوان كلها من متغيّرات `.inv` في `src/app/globals.css` — لا تعتمد على ثيم الصفحة، لذلك تعمل فوق صفحات فاتحة أو داكنة.
- **الطباعة تعزل الفاتورة تمامًا:** `body.printing-invoice` + طبقتان: `visibility` (تعمل في كل المتصفحات) و`:has()` الحديثة التي تُخفي كل ما عدا سلسلة الفاتورة، فيصبح ارتفاع المستند = ارتفاع الفاتورة (ورقة واحدة بلا صفحات فارغة).
- حروف العربية **بلا `letter-spacing`** (لأنه يفصل الحروف المتصلة) — يُستخدم `word-spacing` بدلًا منه، والتتبّع الحرفي للاتيني فقط (`.inv-latin` / `.inv-doc-label-en`).
- الصور المصغّرة في الفاتورة **بلا `lazy`**، وزرّ الطباعة ينتظر تحميل الصور قبل `window.print()` — حتى لا تظهر مربعات فارغة.
- تفاصيل الطلب كلها من الطلب المحفوظ على الخادم؛ لا تُحسب أي قيمة في الواجهة.

### الملفات

- `src/components/invoice/InvoiceDocument.tsx`: مستند الفاتورة المشترك (عميل).
- `src/components/shop/OrderInvoice.tsx`: غلاف العميل (زرّ الطباعة + إرسال بالبريد).
- `src/lib/server/invoice.ts`: `buildInvoiceText` (واتساب/نص) و`buildInvoiceHtml` (بريد) — الأخير **`async`** ليبني روابط صور مطلقة عبر `publicBaseUrl()`.
- مفاتيح النصوص الجديدة في `src/lib/i18n/dict.ts`: `invoiceDate`، `invoiceOrderRef`، `invoiceItemsCount`، `invoicePayment`، `invoiceCod`، `invoiceCompareAt`، `shipTo`، `invoiceTerms`، `invoicePolicyShip`، `invoicePolicyReturn`، `invoiceKeepRef`، `invoiceElectronic`، `invoiceSeal`، `invoiceThanks`.

### للتراجع

احذف كتلة `.inv*` + كتلة `@media print` من `globals.css`، وأعِد `InvoiceDocument.tsx` من نسخة أقدم — يعود الشكل السابق بلا أي تعديل على الخادم أو قاعدة البيانات.

## 11) قائمة الاختبار قبل التسليم

نفّذ ما يلي بعد إعداد المتجر:

- [ ] **التسجيل والجلسة:** إنشاء حساب جديد ← دخول تلقائي؛ الخروج ← إعادة الدخول.
- [ ] **إعادة تعيين كلمة المرور:** «نسيت كلمة المرور» ← رابط (SMTP أو وضع التطوير) ← تعيين كلمة جديدة ← الدخول بها.
- [ ] **عزل العملاء:** حسابان مختلفان لا يرى أي منهما بيانات أو طلبات الآخر.
- [ ] **منع العميل من الإدارة:** فتح `/admin` بجلسة عميل عادي ← يُحوَّل إلى `/admin/login`؛ و`GET /api/admin/stats` يرجع 403.
- [ ] **إدارة المنتجات:** إضافة/تعديل (السعر والخصم والأحجام والمخزون والصورة)/إخفاء/حذف من لوحة الإدارة.
- [ ] **إنشاء طلب واحد:** إضافة للسلة ← إتمام الطلب ← يُنشأ **طلب واحد فقط** (اضغط «تأكيد» مرتين للتأكد من منع التكرار).
- [ ] **صحة المجاميع:** السعر الظاهر في التأكيد = (مجموع البنود − الخصم + الشحن + الضريبة)، ويطابق سعر المنتج في لوحة الإدارة.
- [ ] **رقم واتساب المدير:** بعد التأكيد يُفتح رابط واتساب على **رقم المالك المضبوط**، ولا يظهر الرقم في الواجهة.
- [ ] **واتساب على الجوال والحاسوب:** الرابط يفتح تطبيق/واتساب ويب بسلوك سليم في الحالتين.
- [ ] **إدارة الطلبات:** ظهور الطلب في لوحة الإدارة، البحث برقم الطلب/الاسم/الجوال، تحديث الحالة والملاحظات، والتصدير CSV والطباعة.
- [ ] **الاستجابة على الأجهزة:** تخطيط سليم على أندرويد/آيفون/سطح المكتب (شرائط، قوائم، أزرار `min-h-11`).
- [ ] **ثبات البيانات:** إعادة تحميل الصفحة وإعادة تسجيل الدخول ← تبقى السلة والطلبات والملف الشخصي.

## 14) استكشاف الأخطاء

- **«SESSION_SECRET مطلوب في الإنتاج»:** عيّن قيمة ≥16 حرفًا.
- **«APP_URL إلزامي في الإنتاج...»:** عيّن `APP_URL=https://نطاقك` في `.env.local`. هذا مقصود: بدونه لا يُبنى أي رابط بريد (تحقق/إعادة تعيين/فاتورة) تفاديًا لتسميم الروابط عبر ترويسة `Host`.
- **صور لا تظهر في Firebase:** تأكد من إنشاء Storage bucket، ومن `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`، ومن نشر `storage.rules`.
- **خطأ فهرس في Firestore:** انشر `firestore.indexes.json` (يحتوي فهرسي `orders` و`reviews` المطلوبين للفرز/الفلترة).
- **لا يفتح واتساب:** تأكد من ضبط رقم المالك في الإعدادات (أرقام فقط مع رمز الدولة بدون +). الموقع يعرض بديلًا واضحًا عند عدم توفر واتساب.
- **نجحت الاستعادة لكن البيانات قديمة:** أعد تشغيل السيرفر بعد الاستعادة (المحرّك المحلي يخزّن مؤقتًا حسب وقت تعديل الملف).
